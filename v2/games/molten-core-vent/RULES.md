## 规则真值

题面是 `width × height` 个方格，与 `(width+1) × (height+1)` 个网格交点。每个方格有且只有两种最终状态：

- `\`：连接该格左上与右下交点；
- `/`：连接该格右上与左下交点。

游戏过程允许方格暂时留空，但通关时必须同时满足：

1. 每个方格都已放置恰好一块斜向导流板；
2. 任何有数字的交点，在该点端接的导流板数量恰好等于数字；
3. 把交点视为顶点、导流板视为边时，整张图中不得出现任何闭环。

数字缺失不等于 `0`；没有数字的交点仍受全局无环条件约束。局部数字全部对上但存在闭环，或全局无环但仍有空格，都不是完成状态。

## 操作契约

- 正向循环：空 → `\` → `/` → 空。
- 反向循环：空 → `/` → `\` → 空。
- 直接输入 `\` 或 `/` 会将当前格设为对应方向；退格会清空当前格。
- 同状态设置、越界坐标或非法编码都是原子无效操作，不改变局面也不增加操作数。

## 固定题面与唯一性证明

六关分为 `4×4`、`5×5`、`6×6` 三档。发布题的题面、ID、seed 和内置答案全部固定。独立回溯求解器使用数字上下界、全局并查集无环判定与 MRV 搜索，并以 `limit=2` 搜索第二解。六关均已证明搜索未截断且解数恰为 `1`，唯一解与内置 `solution` 完全一致。

教程固定使用 `ember-gate-1101`：真实初始态为 16 个空格；执行 `0,0:B` 后左上格为 `\`、已安装 1 块导流板、左上角“1”测点满足；内置唯一解完成态为 16 块导流板、17/17 数字测点精确满足且全局无环。

## 主题映射

| 规则概念 | 世界元素 | 视觉与操作 | 不得改变的含义 |
| --- | --- | --- | --- |
| 方格 | 黑曜石泄压舱 | 独立金属舱盖 | 每格最终恰好一块导流板 |
| `\` / `/` | 陶瓷导流板 | 两种明确斜向、点按循环 | 只连接对应两个对角交点 |

| 满足全部条件 | 熔心稳定 | 冷却青光扫过舱面 | 全填、数字精确、全局无环缺一不可 |

## 激励、存档与完成事件

- 每关首次稳定、个人最佳操作数和“全程未触发数字/闭环冲突”徽章分开记录；不虚构 `par` 或最少步承诺。
- 私有前缀：`ten-realms-v2:games:molten-core-vent:`；教程版本 `v1`。
- 存档只保存合法操作序列，恢复时从固定题面逐步重放，不直接信任浏览器中的棋盘、完成布尔值或分数。
- `runId` 每次新开/重开都重新稳定生成；`eventId = molten-core-vent:{runId}:complete`。
- 完成 payload 固化从官方题面实际执行的规范 `timeline`；创建、outbox 恢复和投递前都重新逐步回放，并核对最终完成、题面 seed、难度、步数及稳定 run/event ID。缺失时间线、伪造步数或不能真实解题的 pending 会被丢弃。
- 完成 payload 必须先成功写入本地 records、未交付 session 标记与 `outbox:v1`，才允许调用 `RealmArcade.complete`；其中任何一次写入失败都保持 fail-closed，内存兼容队列也不算宿主确认。宿主同步接收成功后再移除 outbox，失败时按 `eventId` 原样重试；页面启动和两种 realm-ready 事件都会用同一完成时间与 event ID 补齐部分写并重试。
