# 星屑勘测站（Stardust Survey）规则契约

## 身份、来源与归属

- 合集批次：十境谜游馆 `v3.0`
- slug：`stardust-survey`
- 主题：星屑勘测站；玩家是深场巡测员，扫描安全星域并标出暗物质扰动。
- 规则原型：Mines / Minesweeper（扫雷）。
- 规则与参考实现来源：[`ebnbin/puzzles`](https://github.com/ebnbin/puzzles)，固定参考提交 `5a9e1795a3324e0f6433b79fbe31cbd9b12048a3`；对应中文规则 `doc-zh/mines.html`、Portable Puzzle Collection 参考实现 `vendor/sgtpuzzles/mines.c`。
- 许可：上游仓库与 vendor 许可证声明见仓库根目录及 `v3/THIRD_PARTY_NOTICES.md`。本目录的主题、固定关卡、规则引擎、界面、SVG 教程和存档实现均为本项目独立重写，不复用上游视觉资产。

## 规则真值

### 棋盘与读数

- 棋盘为 `width × height` 的矩形，索引从左到右、从上到下：`index = y × width + x`。
- 每一关有固定、排序过且不重复的 `mines[]`。`numberGrid(level, mines)` 以该集合重新计算数字；绝不从教程、存档或 DOM 信任数字。
- 非扰动格的读数是八邻域内的扰动个数，邻域向量严格为 `dx ∈ {-1, 0, 1}`、`dy ∈ {-1, 0, 1}`，去掉 `(0,0)`；边角格只有实际存在的邻格。
- 每格的可见状态只可能是 `covered`、`marked`、`revealed` 或 `exploded`。黄旗是玩家笔记，不改变 `mines[]`、读数或胜利判定。

### 操作与状态转换

| 操作 | 条件 | 规则真值 |
| --- | --- | --- |
| 扫描 `scan` | 活跃局、覆盖格 | 若是本局第一次真正扫描且目标为扰动，按关卡 seed、目标索引和固定候选顺序把该扰动移到目标及其八邻域之外的第一个空位，再重算全盘数字；其余扫描不改题面。安全格揭开；读数 `0` 用八邻域洪泛展开。 |
| 标记 `mark` | 活跃局、覆盖或已标记格 | 在 `covered ↔ marked` 间切换；计一次操作，但不计扫描、不展开、不改变胜利。 |
| 合鸣 `chord` | 活跃局、已揭开的正数格 | 只有相邻黄旗数恰好等于本格读数时，才一起扫描全部未标邻格。错旗会使其中真实扰动爆发，合法地进入失败态。 |
| 撤销 `undo` | 有上一项成功操作 | 恢复该操作之前的可玩局面及操作数；若撤销了触发扰动的操作，`errors[]` 仍保留命中的索引，作为不参与规则判定的本局返工记录。 |
| 重启 | 任意 | 生成新的 run ID，重置为该固定关卡。 |

无效点击（扫描旗帜、已揭格上的不成立合鸣、失败或完成后的普通输入）是原子 no-op：棋盘、历史与操作数均不改变。

### 失败与完成

- 扫描真实扰动，或合鸣因错误旗帜扫到扰动时，命中格变为 `exploded`，局面为 `lost`。不能再作普通操作，但可以撤销。
- `errors[]` 是诊断日志：红框提示玩家本局曾误触的位置。它不会把安全格变成扰动、不阻止完成，也不会因撤销而悄悄消失。
- 完成谓词为**所有非扰动格都处于 `revealed`**。不要求把所有扰动插旗；没有误旗、不存在局部冲突或“旗数刚好”等都不是替代完成条件。
- 胜利、失败、已完成布尔值、分数与奖励都从 `replayTimeline()` 的真实动作重算，不能从 `localStorage` 的声明字段伪造。

## 固定关卡、无猜证明与参考线

每个扇区固定保存 seed 与扰动索引，并且 `validateLevel()` 会重新计算八邻读数。`deriveNoGuessTimeline()` 只使用已揭数字及黄旗的两条局部推理：

1. `读数 − 相邻黄旗数 = 未知邻格数` 时，未知邻格都必须是扰动，依次标记；
2. `读数 = 相邻黄旗数` 时，其余覆盖邻格都安全，依次扫描。

它从 `firstSafe` 启动，不能读取隐藏答案来决定下一步；五关均在不触雷、无需分支猜测下走到真实完成态。`par` 是此确定性协议生成的参考操作数，不声称数学最少步数。

| 难度 | 关卡 ID | 尺寸 | 扰动数 | seed | 首扫 | `par` |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 入门 | `orbit-window` | 5 × 5 | 4 | 31011 | 0 | 4 |
| 入门 | `comet-ledger` | 5 × 5 | 5 | 31027 | 0 | 8 |
| 巡测 | `ion-shelf` | 6 × 6 | 7 | 42041 | 0 | 11 |
| 巡测 | `nebula-corridor` | 6 × 6 | 8 | 42083 | 0 | 15 |
| 深空 | `dark-field-array` | 7 × 6 | 11 | 53019 | 0 | 17 |

难度改变真实网格规模和扰动数量；不是只改名称或色彩。

## 主题映射

| 原规则概念 | 世界元素 | 非颜色线索 | 玩家动作与反馈 | 不可改变的含义 |
| --- | --- | --- | --- | --- |
| 未知格 | 待测星域 | 圆形扫描环与斜向星轨 | 扫描或标记 | 尚未得知安全性 |
| 数字线索 | 八邻扰动读数 | 等宽数字与可读标签 | 扫描后出现 | 周围八格的真实扰动数 |
| 地雷 | 暗物质扰动 | 黄旗、爆发星芒、红色返工框 | 标记/误触 | 扫描会失败；旗不等于真值 |
| 零扩展 | 安静星海 | 连续凹面格与状态提示 | 自动展开 | 标准八邻零值洪泛 |
| chord | 合鸣扫描 | `✧` 图标和“读数=旗数”文案 | 点击已揭数格或工具按钮 | 同时开未标邻格，错旗仍会失败 |
| 胜利 | 深场测绘完成 | 全盘扫描面与 FIELD CLEAR 徽记 | 完成弹层 | 所有安全格已揭开 |

主题材质是深蓝舷窗、青色扫描束、黄铜旗记与紫色星尘；覆盖、读取、标记、爆发和历史错误除了颜色外分别有环、数字、旗形、星芒和叉号，避免状态混淆。

## 教程真值链

三张 SVG 均来自固定首关 `orbit-window`（seed `31011`，扰动 `4,10,20,24`），并带有 `data-tutorial-level`、`data-state`、`data-action`、`data-mines` 等可审计元数据。

1. `tutorial-elements.svg`：真实 `initial` 状态；棋盘全覆盖，首扫安全格为 index `0`。
2. `tutorial-action.svg`：对同一状态调用玩家同源 `scanCell(initial, level, 0)` 得到的 `action` 状态。零扩展揭开 20 个安全格，index `15` 和四个扰动仍覆盖。
3. `tutorial-goal.svg`：本关真实 `solved` 状态；教程回放在最后一次安全扫描前额外标记了四个扰动，所有 21 个非扰动格仍由引擎判为 `revealed`。黄旗不被计入完成谓词，四步核心无猜参考线可省去最后两枚旗。

图片使用 `viewBox="0 0 800 450"` 与 `preserveAspectRatio="xMidYMid meet"`，HTML 使用 `object-fit: contain`。首次进入自动弹出；可跳过、完整浏览，或从原生 `#tutorial-button` 重看。已读标记仅写私有 `tutorial:v1`，不会清理进度、纪录或奖励。

## 激励、存档与完成事件

- 每关首次完成写入本机勘测日志；之后以更少操作刷新个人最佳。页面只把 `par` 表示为“建议参考线”。
- 存档前缀严格为 `ten-realms-v3:games:stardust-survey:`，键为 `session:v1`、`settings:v1`、`tutorial:v1`、`records:v1`、`outbox:v1`。不使用 `localStorage.clear()`，不枚举或删除其他游戏键。
- session 只接受 schema v1、已知 level、合法 run ID 和白名单动作；恢复时回放 `scan / mark / chord / undo`，并逐字段对比回放局面。损坏、伪造完成或错误的棋盘会被丢弃为新局。
- 完成 payload 的 schema 为 `ten-realms-v3.game-complete` v1；稳定 event ID 是 `stardust-survey:<runId>:complete`。payload 包含关卡、seed、动作数、扫描数、旗数、参考线、时间戳和可回放 timeline。
- 严格顺序：先保存完成 session 与本地 records，再持久化私有 outbox，最后只调用一次 canonical host（优先 `window.TenRealmsV3`，兼容 `window.RealmArcade`）。Host 不可用或抛错时保持同一 event 的 outbox/兼容队列；成功后才删除 outbox。records 和队列均以 event ID 去重。
- 同一局在胜利后撤销再补回，保留原 run ID 与 event ID，已成功投递时不会重复调用 host 或重复增加本地战绩。

## 交互与验收范围

- 主操作使用点击/触摸模式切换；右键也可快速标记。核心单元和工具至少 `44 × 44 CSS px`。
- 键盘支持方向键、Enter/Space、M、C、U 和 Esc；每格有行列与状态可读标签。
- 基线布局为 320×720、390×844 与 1280×720。最宽 7 列在 320px 时以 1px 间距紧贴棋盘容器，仍保留至少 44px 的单元，无整页横向滚动。
- 教程、胜利层与共享层不会并排打开；弹层锁背景且内部可滚动，关闭后恢复触发按钮焦点。`prefers-reduced-motion` 保留静态状态但移除闪烁和放大动画。
