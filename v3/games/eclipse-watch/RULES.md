# 蚀光巡检署（eclipse-watch）规则契约

## 身份、来源与许可

- 批次：十境谜游馆 3.0；玩家身份为负责日蚀边界读数的巡检员。
- 原型：Simon Tatham Portable Puzzle Collection 的 **Range**（Nikoli 的 Kurodoko / Kuromasu）。
- 冻结来源：`upstream/main` 的 `ebnbin/puzzles@5a9e1795a3324e0f6433b79fbe31cbd9b12048a3`；规则说明 `doc-zh/range.html`，参考实现 `vendor/sgtpuzzles/range.c`，触控映射参考 `src/games/range.ts`。
- 上游原型、规则说明和参考实现遵循 MIT License。本目录的主题、前端实现和 SVG 是新创作，没有复制上游绘制资产。

## 不变的规则真值

棋盘为 4 邻接的 5×5 或 6×6 格。带数字的读数灯永远是白格，不能涂黑。其余格拥有黑影、白点笔记、未知三种界面状态：

- 黑影会截断上下左右光束；任意两个黑影不能正交相邻。
- 任意非黑格均为白色巡界的一部分，所有白格必须正交连通。
- 每个数字等于从该灯出发沿四个正交方向，直到边界或黑影为止看见的全部白格数，灯自己只计一次。
- 白点笔记只表示“我暂时相信这里不是黑影”。和未知格一样，它不截断光束、不会改变读数、不会单独制造胜利；这保留了上游将 EMPTY/WHITE 同视为非黑格的规则语义。

当且仅当所有读数精确、黑影无正交相邻且非黑格连通时完成。未知格不等同于黑格；它被视作仍可见的白色空间，故玩家不能用白点笔记遮掩错误光束。

## 主题映射

| 原规则概念 | 巡检署元素 | 操作反馈 | 不得改变的含义 |
| --- | --- | --- | --- |
| 数字线索 | 白色读数灯 | 实时 `当前/目标` 读数 | 线索永远白色 |
| 黑格 | 日蚀黑影 | 黑月圆标，截断光束 | 不得正交相邻 |
| 白色/空格 | 巡界空间 | 淡色地块 | 都可被光穿过 |

| 视线 | 光束 | 点击灯后高亮可见格 | 仅四方向到边界/黑影 |

## 固定关卡与唯一性

五个固定档案：`first-umbra`、`crescent-file`、`penumbra-ledger`（5×5），`eclipse-conduit`、`totality-watch`（6×6）。`levels.mjs` 固定 ID、seed、线索与仅作回归基准的 0=白、1=黑答案。

`logic.mjs#solveLevel` 是不读取 `level.solution` 的独立二色搜索器。它从线索格出发，对每个未知格枚举黑/白，并以“相邻黑影”与“每束光的最小/最大可能读数”剪枝，在叶节点复核完整白色连通。每个固定题面在专测中要求 `count === 1`、`truncated === false`，唯一性不依赖内置答案。

## 回放、存储和激励

- 回放动作：`{ type: "mark", cell, mark }`，`mark ∈ {-1,0,1}` 分别是未知、白点笔记、黑影。线索、越界或同态操作都是 atomic no-op。
- 白点笔记存入回放以便恢复玩家桌面，但不增加 `moves`，完成 payload 的效率动作数只统计黑影的设置或移除。
- 撤销删去最后一条动作并从初态重放；若从已完成盘面破坏黑影配置，新 run ID 生成，旧完成事件保持可去重。
- 所有私有键以 `ten-realms-v3:games:eclipse-watch:` 开头。恢复时必须重放时间线并验证状态，不能信任保存的完成旗标或伪造答案。
- 完成 ID 为 `eclipse-watch:<runId>:complete`。先持久化私有 outbox，再调用 `window.TenRealmsV3` 或兼容 `window.RealmArcade`；重复投递同一 ID 不重复奖励。
