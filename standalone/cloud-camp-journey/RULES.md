# 云野露营：规则与关卡契约

批次 2026-09-08，slug `cloud-camp-journey`。原型为 Simon Tatham 的 Tents。规则参考：https://www.chiark.greenend.org.uk/~sgtatham/puzzles/doc/tents.html ，中文参考：https://github.com/ebnbin/puzzles/blob/main/doc-zh/tents.html 。原项目参考实现位于 `v2/games/cloud-camp`，2026-09-08 只读参考，其仓库 HEAD 为 `374d2eee951c8f6aa0bbc829e9cceaa127596b7c`。源项目采用 MIT License，Copyright (c) 2026 Ten Realms Arcade contributors；许可保留在本包来源文件中。本次规则模块、独立验证器、关卡生成和主题为新实现，没有复制上游美术。

## 不变的玩法

棋盘为 4×4 至 7×7 正方形，行列从上到下、从左到右。代码以 `index = row * size + col` 存储零基格子编号。固定树不能移动或填写；每个非树格的状态为 0 未知、1 帐篷、2 标空，树格在数组内始终保持 0。

每棵树对应一顶帐篷，每顶帐篷对应一棵树，树与帐篷必须上下左右相邻。一个帐篷可以在图形上挨着多棵树，但最终必须存在覆盖全部树和帐篷的一一匹配，并不要求每棵树在图形上只挨着一个帐篷。帐篷彼此不能上下、左右或斜角相邻。每行、每列的帐篷总数必须恰好等于其配额。零就是零，不能当作缺失线索。

只有同时满足所有配额、八邻域不接触和全局完美匹配才通关。标空只是笔记，不要求全部未知格标空；未标空不能阻挡已正确的通关。放错帐篷与标错空格是可纠正的过程状态，不扣命、不锁局、不直接失败。错误操作允许写入有效非树格并显示冲突，以保留经典自由填写语义；树格、越界、非法状态、同值重复输入严格原子 no-op，返回 `accepted:false`。

界面采用先选格、再选择搭帐篷/标空/擦除的精确输入。撤销恢复动作前的不可变棋盘快照；重开清空本局状态，创建新 runId。棋盘引擎不依赖 DOM、存储、奖励、计时或动画。

## 全局真值与独立证明

`src/engine.mjs` 的 `maximumMatching` 使用增广路径求完整二分图最大匹配，不能由“每棵树附近有帐篷”或局部贪心替代。测试包含一个 Hall 反例：4 顶帐篷和 4 棵树各自都有邻居，行列全部精确、帐篷不接触，但最大匹配仅为 3，禁止结算。

`src/solver.mjs` 不导入规则引擎，不读取 `level.solution`。它枚举行中所有满足配额的独立帐篷位掩码，逐行检查上下/斜角接触和列容量，在叶子用另一个树分配 DFS 验证全局匹配。对每题设置 `limit:2`，搜索耗尽且只发现一个帐篷布局才声明唯一；第一次找到答案或截断绝不算唯一。唯一性指帐篷布局，不声称树帐对应本身只有一种。所有 180 题均有逐题证据 `release/level-proof.json`，测试用抛异常的 solution getter 确保验证器不读取答案。

## 主线、复玩与真实递进

主线 60 关，6 章，每章 10 关：

|章|规模|学习重点|收藏物|
|---|---|---|---|
|晨露草甸|4×4|零配额与行列计数|晨露帐篷|
|杉林风声|5×5|上下左右的树帐关系|松风天幕|
|溪谷野餐|5×5|八邻域排除|花坡野餐垫|
|日落山坡|6×6|树候选与行列交叉推理|溪光营灯|
|星夜营地|6×6|共享候选与一一匹配排伪解|暮云帐篷|
|云海远行|7×7|多次全局假设与综合约束|星河观景台|

所有规则从第一关起始终有效；章节逐步增加线索交织程度，并不在中途改变胜利规则。从 12,970 个已唯一验证且按 D4 去重的候选中，使用固定顺序的逻辑推演、独立配额策略停滞、树匹配排除的几何伪解、全局提示次数、搜索分支与节点数测量后挑选。实现评分仅用于同章内非降排序，不把所有章节强行排列成同一人类难度量表；章节间依照所需技能转移，允许学习新技能时重新留出缓冲。评分不是最优步数或人类难度测量，固定提示策略需要反设也不代表所有更高级的人类逻辑都必须猜测。

为防止“深度”只体现在标题与尺寸，`quotaOnlyAudit` 独立执行一套偏强的纯配额策略：免费排除无正交树和与现有帐篷八邻接的位置，然后只允许“剩余候选数等于配额就全填”和“行列已满就标空”。它不调用 `logicalHint`、不读答案、不使用树唯一候选或匹配。证明文件记录每题的全部审计动作和精确停滞棋盘，可重放复算。即使免费获得这些邻接知识，第四章仍有 **8/10** 题无法仅靠配额完成；第五章和第六章均为 **10/10**。

第五章的 **10/10** 题还有更直接的树约束证据：完整搜索发现至少一个帐篷数量、全部行列配额、帐篷间距和“每顶帐篷邻接某棵树”都合法的几何布局，但它无法覆盖全部树。若省略每棵树的独立归属要求，就会得到额外伪解。`matchingRejectedWitnesses` 保存具体伪解，测试分别核对几何条件正确与引擎完美匹配失败；因此这些题确实需要额外树约束／一一匹配推理。第六章 **10/10** 题在固定完整提示策略中使用 **2–4 次** 全局反设，且每题搜索分支点不少于 4。

这些门槛在生成脚本与测试中双重执行，不满足便失败。`release/level-proof.json` 的 `depthAudit` 为逐章汇总，逐题 `difficulty`、`quotaOnlyAudit` 和 `matchingRejectedWitnesses` 为原始证据。可以用 `node --test tests/rules.test.mjs` 重复检查。

生成先随机布局不接触帐篷，再完整分配邻接树，推导行列配额并验证唯一。不是固定题旋转。对题面连同配额计算 D4 规范签名，4 次旋转和 2 次镜像的等价题均去重，60 主线和 120 额外复玩题在这一意义下全部互异。`node scripts/generate-levels.mjs` 可确定性重建题库和证据。

每日营地以本地年月日稳定映射到 120 道额外验证题。种子旅途以文字种子稳定打乱同一额外题库，默认抽取 10 题且单条旅途不重复；不同日期、不同种子之间可能重现同一题，不宣传无限关卡。主线和额外题库互不重用。

## 提示、教程与非惩罚成长

提示先检查当前棋盘是否可延伸为合法终局。无解时明确说明需要纠正，返回某个错误帐篷/标空的清除动作。可解时优先解释行列剩余配额、已满行列、帐篷间隔、无邻接树和树的唯一候选；必要时以反设完整搜索证明一个位置必填或必空，文案明确称为综合推理。提示不读存储答案、不伪装为局部推理；使用提示不扣已得收藏与进度。

教程使用第一关的真实树、行列和引擎棋盘，三图分别为初始状态、一次合法放帐与完成状态；已标空不是完成所必需条件。初次自动展示、可跳过、可重看，教程版本独立于主存档。

主题把规则概念映射为露营手账与立体纸景草甸：树为固定纸树，帐篷为折纸三角实体，未知为草甸格、标空为小叉/草地笔记，配额为手账边栏数字。选中、帐篷、树、标空和错误除色彩之外还有形状或文字区分。收藏来自首次关卡/章节完成与探索，不用移动次数强套最优评分，不以断签惩罚。

## 存档与宿主边界

私有键前缀遵循 `mini-polish:cloud-camp-journey:v1:`。稳定 runId、completionId、rewardClaimId，完成 payload 使用 `{schemaVersion:1,gameId,levelId,mode,runId,completionId,rewardClaims,metrics,completedAt}`，先持久化再通知可选宿主；重复投递由稳定身份去重，宿主缺席不妨碍通关。存档棋盘通过严格数据验证与历史重放确认，不信任保存的“已完成”标志；无 `localStorage.clear()`，不删除其他游戏数据。会话层的恢复、重复结算与重开测试由独立存储模块负责。

## 验收与范围

`npm test` 运行规则、会话及发布校验；仅规则也可运行 `node --test tests/rules.test.mjs`。`npm run build` 仅构建本目录到自身 dist。规则测试涵盖 180 题独立证明、D4 去重、章节深度门槛、配额策略停滞重放、匹配伪解逐项核验、所有主线提示可达、非法/稀疏输入、全局匹配反例、真实多解与搜索截断、确定性生成、有限复玩池和教程关全状态子集对照。最终 QA.md 记录构建、ZIP 审计、手机尺寸浏览器验证和未覆盖实体设备项。
