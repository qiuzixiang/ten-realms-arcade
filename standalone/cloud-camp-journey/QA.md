## 运行中保存故障

以专用本地 QA 页面，在正常游玩之后让本游戏命名空间的 `setItem` 抛错。随后实际放帐立即出现“当前未能保存”提示，底部不再显示自动保存；恢复写入后继续一次操作并刷新，两个帐篷完整恢复。截图 `release/storage-failure.jpg`。测试同时覆盖 hint / undo / complete、outbox 不提前发送、主存档未成功时教程小键成功不会误报恢复。

复现：`PORT=4282 QA_HARNESS=1 node scripts/serve.mjs`，打开 `/qa-storage.html`，用“模拟保存失败”和“恢复写入”按钮测试。该入口仅在本地服务明确启用时存在，故障脚本不进入 ZIP。

## 可重放浏览器脚本

`npm run qa:browser` 显示调用说明，不会冒充自动启动浏览器。先在 Codex CUA 建立此游戏专用 tab 和 viewport 能力，再在同一 CUA 会话执行：

```js
const qa = await import('file:///绝对路径/cloud-camp-journey/scripts/browser-qa.mjs');
await qa.runBrowserQA({tab: campTab, viewport});
```

脚本只操作传入标签页，通过真实按钮游玩，写入自身 `release/` 截图和报告。它会重开本测试 origin 的当前游戏局；使用测试端口，不要对用户正式进度运行。
