# 规则、来源与数据契约

## 规则真值

一个关卡包含方阵尺寸、初始 0/1 明暗和每口铃的固定影响集合。影响集合含自身，集合内部不重复，各按钮模板互不完全相同。合法输入是现存铃的整数索引。按下后，集合内每个状态做 XOR 1，集合外不动；每个实际按动计一步。所有位置同时为 1 才完成。

同铃按两次恒等，操作顺序可交换。多解合法，不能要求唯一敲击序列。不存在候选落子判胜、动画判胜或凭缓存 completed 字段判胜。非法索引或损坏状态不会部分改变局面。撤销从历史重放前一状态并减少计步；通关后撤销会建立新的 runId，既有结算保持不变。重开是新 run，历史归零，收藏与记录保留。

每关公开的最少次数由运行时 GF(2) 消元并完整枚举零空间，以及独立的折半异或枚举两种算法交叉验证。实际关卡零空间维数 0–4，最高仅枚举 16 个候选按键集合；运行时上限为 14，超过预算的题不会进入题库。证明的是最少按动次数，不是唯一操作顺序，也不是人类体验难度。

从全亮目标按确定 seed 扰动；筛选所需最少步数后检查八种几何对称及任意顶点重编号的有向、带初态颜色联动图同构，最终 60 题互不重复。图颜色散列仅用作必要条件过滤；匹配候选再做精确邻接回溯，不把散列相等当作同构证明。生成失败会抛错，不降格宣称完成。

## 教程与语义映射

稳定教程 ID：`evening-bell-garden-tutorial-v1`。同一个 3×3 十字模板，目标先逆向按 0、4 得到初态；三张图分别是历史 `[]`、`[0]`、`[0,4]`，最后全亮。界面用 1 基编号，因此文字是先敲 1 号，再敲 5 号。

- 二进制状态 → 铜铃明暗；亮时铃舌展开，暗时铃口闭合。
- 影响集合 → 从所选铃出发的风线、箭头及虚线框。
- 合法按动 → 对所有受影响铃同步翻转。
- 全 1 → 庭中花枝展开的完成插画。

教程 SVG 含关卡 ID、全部初态位、逐铃状态与稳定 viewBox，由引擎真实历史生成，不使用生成模型绘制棋盘。装饰封面、图标和花庭均为本项目原创 SVG 代码导出；PNG 封面是矢量插画栅格化，不是游戏实图。`gameplay-mobile.png` 等来自实际构建产物。

## 提示、收藏与每日

提示求解当前实际状态，说明一条最短方案的第一口铃及影响范围，并预选该铃；用户自行确认敲击。打开提示即保留 assisted 标记，撤销不清除；重开才建立新的独立尝试。提示局仍记录通关和普通最佳，不发独立首次／效率徽记。

每个题目 key 的首次独立通关及首次独立达到最少次数各一枚稳定 reward claim。相同成绩重玩、刷新和投递重试不能再次领取。章节点亮十关即收藏庭景，提示通关也计入章节完成。曲谱徽记只从经历史验证的独立记录重建。

每日 key 为 `daily-v1-YYYY-MM-DD`，按本地年月日和题库版本选择第 3–6 章的一道固定题，不声称每日都是新生成或与章节不重复。每日和章节奖励命名空间分离，不设连签扣罚。

## 存档与完成事件

唯一游戏前缀：`mini-polish:evening-bell-garden:v1:`。存档 key 为 `save`；教程已读是独立 `tutorial:evening-bell-garden-tutorial-v1` key。禁止清空其他游戏键。

加载只接受合法关卡／合法日期 key，重放 history；拒绝非法、过长或损坏历史。缓存 lights、moves 和 completed 不参与恢复结果。完成回执的模式、ID、步数、题目、提示标记等也从已验证历史重建；无关奖励声明被滤除。损坏 session 不影响仍有效的记录。存储不可用时提示用户，本轮仍可玩，但不声称保存成功。

完成 payload 包含 `schemaVersion:1, gameId, levelId, mode, runId, completionId, rewardClaims, metrics, completedAt`。`completionId = runId + ':complete'`。先写入记录和 outbox，再尝试可选 `window.eveningBellCompletionHost(payload)`；宿主同步返回 `true` 才确认接收并移出队列，缺失、异常或其他返回值均保留以原 ID 重试。接收方还须按 completionId 与 reward claim ID 去重。没有原生 Bridge 依赖。

存档是设备本地数据，无账号云同步。并行打开多个标签页不提供事务合并；建议同一游戏单窗口游玩。浏览器配额耗尽时会进入明确的保存失败状态。
