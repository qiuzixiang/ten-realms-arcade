# 星滞回收局 · 独立篇设计与规则契约

从现有 30 款游戏中选择 Inertia，是针对“短局、多关卡、移动操作、持续技巧成长”的设计判断，不是经过长期玩家数据证明的留存结论。没有游戏能保证玩家永不厌倦。本作通过不同空间问题、逐步教学、路线改进和可复现新题增加重玩价值；真正的疲劳点仍应在玩家试玩后修订。

## 内容节奏

- 48 个战役关分为 6 章，每章 8 关。关卡顺序逐步强调：墙面制动、引力锚改线、斜向路线、反应堆风险、回返收集和复合路线优化。具体关名、种子、题面和最短步数以 `levels.mjs` 的单一数据源为准。
- 新手关以短且安全的真实谜题学习“一次输入会滑到底”。每章先单独呈现本章空间关系，再与已学关系组合；不将单纯放大地图当作全部难度设计。
- 48 关必须在旋转、镜像归一后仍是不同布局，不把同题的朝向变化作为独立战役内容。最短路径长度、搜索分支与回返关系共同支持难度审核；数值本身不能替代试玩判断。
- 每日航线由本地日期确定，同日重开保持同一题；不设置断签惩罚。远航通过种子生成可重建的新布局，适合战役外继续练习。
- 一局目标始终是安全回收全部能源。三星是可选技巧目标，通关不要求最短，也不要求无撤销。

## 冻结的 Inertia 规则

规则来源为 [Simon Tatham 的 Inertia 文档](https://www.chiark.greenend.org.uk/~sgtatham/puzzles/doc/inertia.html) 与仓库现有 `games/star-drift/logic.mjs` 的经过验证实现。项目参考的上游快照为 [ebnbin/puzzles@5a9e1795a3324e0f6433b79fbe31cbd9b12048a3](https://github.com/ebnbin/puzzles/tree/5a9e1795a3324e0f6433b79fbe31cbd9b12048a3)，上游采用 MIT 许可，保留 Simon Tatham 与贡献者署名。独立篇的界面、关卡、美术和成长系统是本项目制作；不宣称经典规则为原创。

棋盘由墙 `#`、空地 `.`、起点 `@`、停泊锚 `o`、能源 `e` 和反应堆 `x` 构成。坐标 `x` 向右、`y` 向下，均从零开始。

1. 一次输入选择八个方向之一，艇沿该方向连续前进；不能主动在中途刹车。
2. 前方是墙时停在墙前；进入锚点立即停止。起点在离开后仍是停泊锚。
3. 对角移动只检查下一对角格，不被两侧正交格夹角阻挡。
4. 经过尚未收集的能源时将其移除，继续滑行；已收能源所在格成为可经过空地。
5. 进入反应堆立即失败。即使同一次推进较早已收完能源，后续撞堆仍为失败。
6. 一次安全推进停稳且没有剩余能源才获胜。提示、动画、星数、教程状态和存档字段都不参与判胜。
7. 无法离开当前格的方向是无效输入，不增加步数或历史。已胜利/失败后的移动无效。
8. 撤销恢复之前的完整状态，可撤销失败；重开回到原题。没有生命值、体力或付费撤销。

求解器对“位置 × 剩余能源集合”执行等权 BFS，找到的路径才可称最短。预算用完必须标记未证明，不能称无解；战役与生成题都要有可完整回放的解。多条最短路线完全合法，本作不宣称唯一解。

## 主题与反馈

玩家是驾驶微型回收艇的星区领航员，核心动词为“观察、点火、借停、回收”。太空场景承担探索动机，棋盘图形承担精确规则表达。

| 规则元素 | 世界元素 | 视觉和动作反馈 | 规则边界 |
| --- | --- | --- | --- |
| 玩家位置 | 回收艇 | 尖头艇形、推进尾焰、真实起止轨迹 | 动画完成位置与引擎一致 |
| 障碍 | 废弃舱壁 | 实体金属块、明显边缘和阴影 | 不能进入，停在前一格 |
| 停止格 | 引力锚 | 环形实体、减速光环 | 进入即停，能再次出发 |
| 收集物 | 能源芯 | 菱形晶体、逐枚吸收和短促音阶 | 经过就收集，不制动 |
| 致死格 | 反应堆 | 辐射形状与警示纹理 | 进入失败，不只靠颜色区分 |
| 解谜进度 | 星图档案 | 章节节点、星级、首次回收碎片 | 装饰进度不改变胜负 |

降低动态效果偏好下保留状态变化，缩短或移除非必要轨迹位移、闪光与镜头效果。音效由用户设置控制，默认允许声音但须遵循浏览器手势后初始化的行为。棋盘、图例和教程使用代码图形，不能用生成位图代替精确题面。

## 教程与手机体验

首次进入自动呈现“元素 → 一次合法推进 → 真实完成”三张图片卡，支持跳过和随时重看。三张图必须由同一真实关卡经正式规则函数生成，操作前后使用清楚分开的状态。教程版本单独保存，更新时不清除任何关卡进度。

八方向按钮、撤销和提示是移动端的直接操作方式，按至少 44 × 44 CSS 像素检查；键盘和滑动是补充。棋盘不要求精确点击小格。教程与结算模态要锁定背景、管理焦点、支持 Esc，窄屏内容可滚动且图片完整显示。

## 存档、星级与重玩

独立存档仅使用 `star-drift-standalone:profile:v1`；不接旧合集宿主，不覆盖三个旧版进度。`storage.mjs` 不读取其他键，也不调用整库清空。

- 每次新开或重开产生独立 run ID；完成 ID 为 `star-drift:{runId}:complete`。同一 run 刷新或重试结算都幂等。
- 会话保存关卡 ID、模式、生成元数据、规范移动日志和提示次数；刷新时用官方关卡或可复现生成题逐步回放。不信保存的 `status`、艇位置、收集数或分数。
- 完成账本保留真实移动日志。加载时逐条重新回放，重建记录、星数和奖励；某局损坏不影响其他有效记录。超长或含非法动作的日志不能领取奖励。单局日志上限为 512 次推进。
- 不使用提示且最终步数不超过已经证明的 par：3 星；不使用提示但超过 par：2 星；使用提示后完成：1 星。撤销不扣星；本次使用过的提示不会因撤销而消失。
- 每题星数只保留历史最高，每个星级具有稳定 claim ID。首次通关获得 1 枚星图碎片，同题重复相同成绩不会增加星数或碎片。
- 新 run 再次通关会更新真实完成次数；改善路线会更新最少步记录。关卡解锁只依据官方战役 ID 的前一关完成记录，不能靠保存的关卡索引越过顺序；每日航线与远航不受战役解锁限制。
- 存储写入失败返回错误并保留内存进度与旧存档，不声称已保存；界面可以显示未保存状态并在下次操作重试。当前产品没有远端账户或多设备同步。

## 验证与交付边界

存档专项：`node --test standalone/star-drift/tests/storage.test.mjs`。引擎与关卡专项见本目录 `tests/`；仓库集成命令为 `npm test` 与 `npm run build`。

重点验证：全部战役可解与最短路线回放、旋转镜像去重、生成种子重现、当前局提示、矿优先失败、撤销与刷新、同局结算重试、同题再次完成、最佳成绩改善、损坏存档、超长日志、储存失败与命名空间隔离。真实浏览器走查覆盖教程跳过/重看、合法推进、撤销、获胜、下一关及 320 像素视口。

本地开发与验证完成不代表已发布，也不代表已经验证长期留存。发布状态、实际测试结果与尚未覆盖的终端，以最终交付说明为准。
