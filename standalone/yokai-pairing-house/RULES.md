# 规则与状态契约

棋盘为 `(N+2) × (N+1)`；主线 N 为 2、3、4。格内数字是确定的 `0..N`，0 不是空白。两格只可在上下左右正交相邻时配成一间房。数字对无序，例如 `1-2` 与 `2-1` 是同一种组合。完整组合数为 `(N+1)(N+2)/2`，每种必须恰好用一次。

房间操作：连续点两格。点非邻格只改选第一格，不计步；点已配对的同一边会拆房。新房触及旧房时，先预览将拆数量；确认后拆旧建新是一次事务，可一次撤销。没有固定给定房。排除边仅是玩家笔记，不占房间、不参与判胜；被新房触及的排除边会清除。

冲突态允许继续修正。已放重复数字组合会显示冲突；所有格被覆盖但有重复组合仍不胜。只有每格恰好覆盖且每种组合恰好一次才通关。提示先显示一条由已验证唯一题解给出的房间，再由玩家决定是否放入；仅放入才把本局标记为使用提示。

战役题面由固定种子和生成器版本 1 得出，并按水平/垂直镜像及数字重标记去重。保存的 60 题各由不读取内置答案的搜索器找到恰好一解。`src/levels.mjs` 中的答案用于提示和教程，正式判胜只检查当前房间集合。可解、唯一与最少操作是不同承诺；本作不宣称最少步数。

存档前缀 `mini-polish:yokai-pairing-house:v1:`。客户端 9.46+ 优先使用小工具 Storage JS API，旧客户端回退浏览器存储；读档重新核验房间与首通证明，不信任完成布尔值。完成事件字段遵循 `schemaVersion/gameId/levelId/mode/runId/completionId/rewardClaims/metrics/completedAt`，同局 ID 稳定，首通房卡与每日印章按 claim ID 去重，写入完成后才尝试投递可选宿主。

教程版本 `yokai-pairing-house-tutorial-v1`，三张状态都来自第 1 关：初始、一次合法房间操作、正式引擎确认的完成态。教程已读标记独立于关卡进度。
